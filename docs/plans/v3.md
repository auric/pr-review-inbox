Status: done, pending docs/smoke-v3.md. Draft of 2026-10-11 on branch `m1-inbox` at c8d83ce. The spec is prototype/v3/index.html at c8d83ce, plus the review-brief update. ## 1. Scope

- In (UI): three inbox groups, the turn rule, rows that open at their cause, the first task ID on each row, the one-column detail with the reply tree, Files and Commits folds, and j/k between threads.
- In (M2): the inline review brief, the task-ID extractor, the sanitized worktree, the read-only git MCP, the Claude Code runner, the run log tree, the anchor validator, Explain, and the raw output of failed runs.
- In (M3): triage, move, the durable outbox, inline and general posts, and replies with preview and confirm.
- In (M3, docs/plans/replies.md): a copy button on each message, AI reply drafts for all your-turn threads or one thread, and their triage and posting.
- Design only: the issue-tracker ContextSource for Release 2 (section 8).
- Out: incremental "Review changes" runs (D5), a diff viewer, profile editing (M4), `bun build --compile` (M4), and the Bitbucket MCP in reviews.

## 2. Cross-cutting decisions

| Topic | Decision | Reason |
|---|---|---|
| Turn rule | One pure module, `src/shared/turn.ts`. The server groups rows with it. The UI orders threads with it. | Both panes must agree (prototype 1059-1104). |
| Inbox groups | Needs you: your, triage, review, commits, comments. Waiting on others: waiting. Done: quiet, closed (folded). | Prototype 1108-1112. D1 covers closed PRs. |
| Last visit | New column `pull_request.seen_at`. `POST /api/prs/:id/seen` sets it on open. The UI keeps the previous value for "N new since". | The M1 data has no visit time. |
| Product names | `GET /api/meta` returns the forge name. WP10 adds the runner name, tool labels, profiles, and context sources. UI code holds no product name. | User decision. src/web holds 14 hard-coded forge strings today. |
| Web links | File and comment links come only from server links plus the suffixes that Gate A records. | M1 rule: the app invents no URL. |
| Task IDs | Ordered rules in config.json. A Bun Worker runs the regexes with a 100 ms budget per PR. A timeout terminates the worker. | A bounded run time stops ReDoS with no regex dependency. |
| Task links | A chip links to the tracker only through a known URL: the linked-issue URL from Gate A, or the optional `taskLink` template in settings. | The app invents no URL. |
| Workspace | One bare cache clone per repository. Each run gets `git worktree add --detach` at the pinned head. The user's dev checkout is never used. | User decision. History stays in the clone for the git MCP. |
| Git isolation | Every git child gets `GIT_CONFIG_NOSYSTEM=1`, an empty `GIT_CONFIG_GLOBAL`, `GIT_TERMINAL_PROMPT=0`, and no credential helper. Only fetch gets the token, through `GIT_CONFIG_*` `http.extraHeader`. | No user filter, hook, or LFS smudge runs on PR content. Gate 0 used the env form. |
| Run folder | The cwd is the long path of `<dataDir>/runs/<id>/work/` with `repo/` and `context/`. App files sit in `<dataDir>/runs/<id>/app/`. After each run, the runner deletes both per-cwd folders of the CLI. | `--restricted` refuses Reads outside the cwd, so the database, config, and cache clone stay out of reach (Gate B8, B9). An 8.3 short cwd makes the CLI refuse Reads inside it (B4, B9). |
| Subagents | Review agents come from an `--agents` file with read-only tools and `omitClaudeMd`. `--agent rl-main` with the tool `Agent(rl-reviewer)` refuses built-in and user agents. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` keeps agents in the foreground. | User decision. The Gate 0 raw run showed async agents and two result events. Gate B2, B3, and B9 confirm the fix. |
| Prompt trust | The note has its own trusted section. Task IDs, the PR link, and the profile go in as metadata. PR text and tracker text are files, marked as data. | Only the user's own note is an instruction. |
| Result | One zod schema in `src/shared/review.ts`. `z.toJSONSchema` feeds `--json-schema`. The CLI's own schema retries count as the one repair. | BRIEF 7 asks for one schema. This avoids a second paid call. |
| Reply result | A sibling `replyResult` in `src/shared/review.ts`, with its own `replyJsonSchema()`. `reviewResult` does not change. | One shared AI-result schema module (docs/plans/replies.md). |
| Run kind | A reply run is a job kind, `review_run.kind = 'reply'`, not a profile. It keeps the profile's focus, cap, and docs. It shares the one run slot per PR. | docs/plans/replies.md, decision D11. |
| Reply trust | Comment text reaches a reply run only in `context/pr.md`, under the UNTRUSTED banner. The prompt holds only numeric thread and message IDs and the user's note. The validator drops replies to threads that were not requested. | Comments come from other people (R11). |
| Raw output | `review_run.raw_output` keeps the result text, `structured_output`, and the stderr tail, up to 2 MB. The run line and the log show it, read-only, with Copy. | BRIEF A11. The user can see why a run failed. |
| Posting unit | One `post` row per comment to send. It binds body, destination, item revisions, and reviewed heads. No separate approval table exists. | One general comment merges several items. The row is the approval. |
| Test injection | `startServer` takes a `runnerCommand` option. serve.ts and the tests pass the fake CLI. No env switch exists. | Production has no path to an arbitrary command. |
| Typecheck | WP1 adds devDependency `"typescript-5": "npm:typescript@5.9.3"` and the script `typecheck:5`. | Every package ends green on TS 7 and TS 5.9.3, with a pinned lock. |

## 3. Invariants and evidence (M1 guarantees stay)

- I2. Sync writes one transaction per PR after a complete fetch (src/server/sync/engine.ts:290-323). A delete needs absence plus a 404 (m1.md:129).
- I3. The notification claim is one atomic UPDATE (queries.ts:31-36). v3 adds no event kind.

- I5. The parser strips the comment fields severity and state, and the anchor fields srcPath and range start (src/server/bitbucket/schemas.ts:28-61). The recorded comment has severity NORMAL and state OPEN (comment-inline-commit-response.json).
- I6. Inline activities carry `diff.hunks[].segments[].lines[]` with source and destination numbers (activities-inline-anchored.json; integration-check.md:50).
- I7. PR repositories carry `links.clone` (http, ssh) and `links.self`, the browse link (fixtures/bitbucket/pull-request.json).
- I8. A COMMIT anchor with fromHash = target head and toHash = source head returns 201 (integration-check.md:50).
- I9. `git ls-remote` lists `refs/pull-requests/<id>/from`. No fetch of it was tested (integration-check.md:54).
- I10. `--restricted` ignores user, project, and local settings files and confines the file tools to the cwd (CLI 2.1.295 help). In Gate B8 no hook ran, and a Read outside the cwd was refused. `--strict-mcp-config` keeps only app MCP servers (Gate 0 e, B6). `--tools` limits the tool set (Gate 0 f, B8).
- I11. In `-p` mode, an Agent call ran in the background. The stream held two `init` and two `result` events (Gate 0 raw `.gate0/local/run1-f-default.jsonl`, CLI 2.1.295).
- I12. Gate B2, B3, and B9 (CLI 2.1.295): `--agent rl-main` with the tool `Agent(rl-reviewer)` refuses built-in and user agents. `Agent(name)` deny rules also refuse both. `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1` removes only built-in agents, so the runner does not use it. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` forces the foreground and one result event. `--agents` accepts a file with `tools`, `disallowedTools`, and `omitClaudeMd`.
- I13. `taskkill /T /F` ended `claude.exe` and its MCP child (integration-check.md:25).

## 8. Release 2 boundary: issue-tracker ContextSource (design only)

- Interface: `ContextSource = { id, name, check(): Promise<Status>, fetchIssue(key): Promise<IssueContext> }`. `IssueContext = { key, url, summary, status, description, acceptance?, comments[], links[], fetchedAt }`.
- Jira connector: `src/server/context/jira/` with its own REST client, apart from the forge client. Bearer token, `redirect: "manual"`, a timeout, and the CA file.
- Host allowlist: requests go only to the configured origin and the explicit `hosts` list. Any other host or redirect is an error.
- Settings shape: `context.jira = { baseUrl, hosts: string[], caFile?, acceptanceField? }`. The token sits in the OS store as `review-loop / jira-token`. GET returns only `tokenStored`.
- Fetch: one click on a task chip in the brief imports summary, description, acceptance criteria, status, comments, and links into an editable "Imported" block. Keys come from WP2 or WP4.
- Trust: the imported text reaches the run only as `context/task.md`, under an untrusted banner. Only the user's note is an instruction. The prompt never quotes tracker text.
- Trust: Jira never receives PR code. Documentation MCPs never receive tracker text. Coverage names the source, the fetch time, and any missing field.

## 10. Open decisions for the user (recommended default first)

- D1. A closed PR with unread messages or a your-turn thread. Default: it keeps its Needs you reason, with "Merged." first in the why-line. Alternative: prototype order puts it in Done. Reason: A15 and the M1 e2e test.
- D2. Only the target head moved before a post. Default: warn and allow, because the anchor pins fixed commits. Alternative: block as for a source change.
- D3. Findings on removed lines. Default: post them as general comments until Gate A confirms the mapping.
- D4. The "moved" search. Default: the nearest match in the whole file, ties to the lower line. Alternative: a fixed window.
- D5. The prototype's "Review changes" run. Default: Release 2, with targeted re-review.
- D6. Turn caps. Default: 40 for review profiles, 12 for Explain. Tune them after the smoke test.
  - Note: the current caps are 100 for review profiles and 50 for Explain (BRIEF.md). Fix and reply runs use at least 100.
- D7. Subagent blocking. Decided by Gate B2 and B9: the `--agent rl-main` allowlist with the tool `Agent(rl-reviewer)`. The runner adds no deny rules and no built-in switch. Fallback, if a later CLI breaks the allowlist: Agent denied and a flat log.
- D8. Transcripts. Decided by Gate B4: `--no-session-persistence` still writes per-cwd files. The runner passes the flag and deletes `<projects>/<encoded cwd>` and `<TEMP>/claude/<encoded cwd>` after each run.
- D9. Task-ID rules. Default: the union of all rules, in order, deduped, at most 10. Alternative: the first rule with a match wins.
- D10. Documentation MCPs (Microsoft Learn, DeepWiki; BRIEF 10.5) in reviews. Default: on, with the prompt rule to send only public names.
- D11 to D14 (doc MCPs in reply runs, the 25-thread cap, per-thread drafts on any live thread, reply posts check parent and `seen` only): see docs/plans/replies.md.
