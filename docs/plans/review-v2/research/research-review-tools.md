# Research: AI PR review tools and studies (scout, 2026-10-22)

Common pattern: find candidates, then verify/filter in a separate pass; noise control first (nits off by default); line anchors; fix only when it fully solves.

| Tool | Checks | Severity | Noise control | Context | Agent split |
|---|---|---|---|---|---|
| Anthropic plugins/code-review | bugs, logic, security in changed code; CLAUDE.md compliance | binary high-signal or dropped | one validator subagent per issue; fixed false-positive list; "If you are not certain an issue is real, do not flag it" | only CLAUDE.md on the changed file's path; PR title+description to every agent | Haiku gate (closed/draft/trivial/already reviewed), Haiku CLAUDE.md finder, Sonnet summary, 4 parallel reviewers (2 CLAUDE.md, 2 Opus bug), per-issue validators |
| qodo pr-agent /review | key issues (file, start/end line, header), security, tests, ticket compliance, effort, failure modes, risk level | risk_level; "Use high only when the PR introduces a clear bug, security concern…" | "For lower-severity concerns, be certain before flagging… with a concrete scenario"; "only on issues introduced by this PR" | org skills, ticket requirements, CI artifact (untrusted) | one prompt with require_* toggles |
| qodo /improve reflect | suggestions | 0-10; 8-10 only major bugs/security; 0 if wrong; error-handling capped 8; "verify/ensure" capped 7 | second pass rescores; threshold | — | generator then reflector |
| CodeRabbit | wide + linters | profile quiet/chill(default)/assertive; quiet puts minor items in summary | profile, path filters, learnings | path_instructions, guideline files, issue enrichment | profile also sets linter strictness |
| GitHub Copilot review | general | undocumented | — | instructions/AGENTS.md/skills from head branch; MCP context from issue keys | effort Lite/Balanced |
| Greptile | general + graph | LLM judge 1-10 drop <7 FAILED | block comment similar to >=3 downvoted (per-team embeddings) | codebase index | v3 agentic, validates own findings |

Sources: anthropics/claude-code plugins/code-review/commands/code-review.md; qodo-ai/pr-agent pr_reviewer_prompts.toml and code_suggestions/pr_code_suggestions_reflect_prompts.toml; docs.coderabbit.ai/reference/configuration; docs.github.com/en/copilot/concepts/agents/code-review; greptile.com/blog/make-llms-shut-up.

Studies: Greptile "~19% good, 2% incorrect, 79% nits"; prompting could not cut nits without cutting critical comments; feedback learning raised address rate 19% -> 55%+. Google comment-to-code: target precision 50%; 40-50% of previewed edits applied; "Show ML-edit" button doubled previews (research.google/blog/resolving-code-review-comments-with-ml). qodo industrial study arXiv 2412.18531: 73.8% of comments resolved, PR close time 5h52 -> 8h20. ByteDance BitsAI-CR arXiv 2501.15134: RuleChecker + ReviewFilter, 75% precision, metric "Outdated Rate" (commented code later changes).

Top practices: 1 find then verify; 2 only what the PR adds; 3 concrete trigger scenario, no overstated severity; 4 explicit do-not-flag list (nits, linter, style, "might break", rules silenced in code); 5 self-confidence is a weak filter, use rubric with caps; 6 path-scoped rules, quote exact rule; 7 author intent (title, description, ticket) to every agent; 8 suggestion block only if it fully fixes, small; 9 one quiet default, louder opt-in; 10 learn from reactions (addressed/dismissed/outdated rates).
Profiles: one strong default + toggles beats many profiles; parallel specialists only when evidence sources differ (rules vs bugs), not by topic. Inference: one reviewer prompt from selected modules (security, performance, tests, docs, over-engineering) + per-finding verifier; specialists only for deep modes; dedupe by file+range before verify.
Recommendations: stage A candidates {severity, file, start/end line, title, body, trigger_scenario, evidence quote, rule_quote?}; stage B verify (confirmed/refuted/unsure), unsure collapsed "low confidence"; rubric with caps, "please verify" -> question; anchors inside + hunks, evidence quotes the line; default bugs+security+rules at chill, toggles tests/perf/docs/over-engineering + volume quiet/chill/assertive; feed title, description, Jira, path-scoped CLAUDE.md, do-not-flag list; fix edits only when small and complete; replies state outcome, never re-argue; record posted/dismissed/fixed for later suppression.
Not covered: Graphite, Sourcery, ellipsis, claude-code-action, reviewdog, Meta/Microsoft studies, benchmarks.
