# Synthetic Claude Code stream samples

These files are hand-written. No real run produced them. The IDs, paths, texts, and numbers are invented. The event shapes follow the gate runs that integration-check.md records: `type` and `subtype`, `message.content` blocks, `parent_tool_use_id`, and the `task_*` events. The init cwd is `C:\rl-synthetic\work`. The fake CLI (tests/support/fake-claude.ts) replaces it with the cwd of the test. Gate transcripts never go here: `scripts/gate/sanitize-claude.ts` writes them to `.gate0/claude/`.

| File | Use |
|---|---|
| `review-flat.jsonl` | A flat review run with no subagent (Gate B6 shape): init, one Glob of `**/*` in repo, text, and a success result without `structured_output`. CLI version 2.1.295. `claudeStream()` and `derive()` replace init and add the result of each test. Most review and task tests, the e2e server, and the demo use it. |
| `review-agent-tree.jsonl` | A review run with subagents (Gate B9 shape): main Read, refused Read outside the cwd, stub MCP call, Write and Edit with "No such tool available", two refused Agent calls (general-purpose, user-agent-5), one rl-reviewer Agent call with three nested calls, `task_progress` tokens 4413 to 4467, `task_notification` with 5382 tokens, a StructuredOutput call, and a result with `structured_output` (MAGNOLIA, JUNIPER, STUBFACT-5150). |
| `background-agent.jsonl` | A background rl-reviewer (Gate B3 shape): the Agent result at launch names the model, the first result comes before the `task_notification` (4601 tokens), and a second init and result with `origin.kind` task-notification carry the final `structured_output`. |
| `max-turns.jsonl` | One refused Read of a.txt, then a result with subtype `error_max_turns` and the error "Reached maximum number of turns (1)" (Gate B5 shape). |
| `auth-failed.jsonl` | An auth failure (Gate B5 shape): an assistant event with model `<synthetic>` and `error: "authentication_failed"`, then a result with subtype `success`, `is_error: true`, and the text "Not logged in · Please run /login". |
| `no-structured-output.jsonl` | One Read and a success result without `structured_output` (Gate B9 first try shape). |
| `plain.jsonl` | An init that lists Edit, WebSearch, and Write outside the review allowlist. Four inert lines come before the first tool call, so the init tool check ends the run before any tool event. |
| `implement-ok.jsonl` | An implement run (Gate B17 shape, CLI 2.1.306): a Write of `./repo/a.txt`, a Write of `../outside.txt` with `permission_denied` before its error tool_result, a StructuredOutput call, and a result with an implement `structured_output` and 5 turns. |
| `usage-limit.jsonl` | `auth-failed.jsonl` with the field values for a limit from the Agent SDK 0.3.295 types: assistant `error: "rate_limit"` (SDKAssistantMessageError), `rate_limit_info.status: "rejected"` (SDKRateLimitInfo), and `api_error_status: 429`. Gate B did not reach a usage limit, so this shape is not verified (docs/plans/v3.md U9). |
| `session-resume.jsonl` | A session fork of docs/plans/session-consult.md part C: init with the read tools and no MCP server, one Read, one StructuredOutput call, and a result with `structured_output`. Gate B16 confirmed the resume shape on CLI 2.1.301: init lists only the read tools and StructuredOutput, and the result carries `structured_output`. |
| `max-turns-notes.jsonl` | A finder that reaches its turn cap: rl-main text, one Read, one rl-reviewer Agent call with a subagent text and its report, more rl-main text, and a result with subtype `error_max_turns` and no `structured_output`. The result shape follows `max-turns.jsonl`. |
| `max-turns-empty.jsonl` | The same finder with one Read and no text: it leaves no notes. |
| `advisor.jsonl` | A run with `--advisor`: init with `advisor` in `slash_commands` only, two advisor calls, and a result whose usage and modelUsage name the advisor model. The block shapes follow Gate G-ADV run 1 (integration-check.md, section Advisor): a `server_tool_use` block named `advisor`, then an `advisor_tool_result` block in a later assistant event. The second call ends with `advisor_tool_result_error`, from the advisor tool page of the Claude API docs. Gate G-ADV saw no error result. |

Change a file here only when a gate run records a new shape. Then update the tests that read it.
